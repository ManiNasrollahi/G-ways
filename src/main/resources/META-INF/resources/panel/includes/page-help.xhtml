How to manage routes

A route connects an incoming request to an upstream service. The route is evaluated together with its predicates and policies.

Recommended flow

  1. Click New Route and enter a technical ID, display name, and destination URI.
  2. Add one or more predicates to decide when the route matches. For example, use Path for /api/** or Method for GET and POST.
  3. Enable the route and click Save and Publish.

Tip: Keep the technical ID stable; other policies and filters use the route relationship.

How to manage request filters

Filters modify a request before it reaches the service or modify the response before it returns to the client.

  1. Click New Filter and select the target route.
  2. Select a filter type and complete its name and value. The available fields change based on the selected type.
  3. Enable the filter and publish it. Filters are applied in the phase shown in the table.

Tip: Use path and header filters for request changes; use response filters for headers returned to the browser.

How to manage trusted proxies

Trusted proxy patterns identify which upstream proxies may provide forwarded client information such as the original IP address.

  1. Click New Trusted Proxy.
  2. Enter an IP, CIDR range, or supported proxy pattern.
  3. Enable the entry and save it. Disable entries temporarily when you need to stop trusting a proxy without deleting it.

Security: Only add networks and proxy addresses that are fully controlled by your infrastructure.

How to manage the gateway blacklist

Blacklist entries block matching client IP addresses before requests reach your routes.

  1. Click New Blacklist Entry.
  2. Enter the IP address and an optional reason for the block.
  3. Enable the entry and save it. Disabled entries remain available for later reuse.

Tip: Use this for emergency blocks and known abusive clients; keep permanent network controls in your infrastructure firewall as well.

How to configure rate limits

A rate limit protects an upstream route by limiting the number of requests allowed during a period.

  1. Select a route.
  2. Set the period in seconds and the maximum capacity for that period.
  3. Enable the rule and publish it.

Example: Period 60 and capacity 100 allow up to 100 requests per minute according to the gateway's rate-limit strategy.

How to configure retries

Retry policies repeat failed upstream calls using a controlled backoff. They should be used carefully, especially for non-idempotent operations.

  1. Select a route and choose safe HTTP methods.
  2. Set the retry count and the first and maximum backoff values.
  3. Choose a backoff multiplier, enable the policy, and publish it.

Warning: Prefer retries for idempotent operations such as GET. Retrying POST or other state-changing calls can create duplicate actions.

How to configure circuit breakers

A circuit breaker stops sending traffic to an unhealthy upstream after its failure rate crosses the configured threshold.

  1. Select a route and enable the breaker.
  2. Configure minimum calls, the sliding window, failure threshold, and open-state wait.
  3. Define the HTTP statuses that count as failures and provide a fallback URI.
  4. Publish the policy and monitor the upstream recovery.

Tip: Start with conservative thresholds and tune them using real traffic and upstream latency data.

How to configure global CORS

This policy applies to browser requests across the gateway. It controls which origins, methods, and headers are accepted.

  1. Add each frontend origin to Allowed origins.
  2. List methods and request headers used by the frontend.
  3. Add response headers to Exposed headers only when browser JavaScript must read them.
  4. Enable credentials only when cookies or authenticated browser credentials are required.
  5. Set the preflight cache duration and publish the configuration.

Important: Do not use * as the allowed origin when credentials are enabled.

How to manage users

Users authenticate to the control plane and are used by the audit fields on gateway configuration records.

  1. Click New User and provide a unique username.
  2. Set a strong password and complete the name fields if needed.
  3. Keep the user enabled to allow login, then save.
  4. Disable a user when access should be suspended without removing its history.

Security: Never share administrator credentials. Use a separate account for each operator.

Getting started

Use the navigation menu to manage the gateway from the control plane.

  1. Create a route and point it to an upstream service.
  2. Add predicates to control when the route matches.
  3. Apply filters and resilience policies where needed.
  4. Configure security controls such as CORS, trusted proxies, and blacklist entries.
